## 结论与独立运行边界

本阶段的自然语言抽取、校验、一次修复、逻辑拓扑转换由我们自己的 Python/FastAPI 代码实现，接入 CRaaS 的 React 前端。没有启动、调用或依赖参考工程的 Docker、Node 服务、远端服务器或生成接口。

调用链：`TopologyBuild.tsx` → 本地 `/api/topology/jobs` → `generation_jobs.py` → `extraction.py` → `llm_client.py` → 配置指定的模型 API → 自有校验/转换 → 网页。资产位于本项目 `backend/app/assets/topology/`，运行不需要工作区的 `reference/` 目录。仓库自身的 Dockerfile/Compose 仅用于打包我们的服务，不是老师的容器镜像。

“自己实现”指服务和处理逻辑重新实现，不表示所有材料从零编写：实体目录、基础提示词、Schema、训练示例及评测数据参考了老师的材料。目录与基础规则有意保持一致，不能将这些来源表述为完全原创。

参考抽取任务、12条规则和自检要求全部保留。仍有明确的工程适配和扩展，不能声称参考demo的所有API、部署功能及缺陷都逐字复刻。鹏城靶场真实部署不是本阶段已实现能力。

## 脚本行为与补齐内容

| 环节 | 最终实现与参考关系 |
| --- | --- |
| 场景选择 | 名称与别名计分、最高分优先及平分次序一致；额外支持手动指定场景 |
| few-shot | 选择同场景关键词命中最多的一条；六条训练示例ID、实体类型及数量保持一致 |
| JSON/Schema | 用jsonschema实现类型、必填、枚举、长度、格式、数值、数组唯一性与额外字段约束；新增可选bandwidth |
| 语义校验 | 目录成员、唯一ID、端点、自连接、五字段重复关系均保留；撤去参考没有的关系类型硬白名单 |
| 一次修复 | 对话保留原始输入、上次输出、校验错误；最多修复一次，不按分数重新生成 |
| 图标 | 补齐raw_name/name、通用终端、云网络、CE/ECR；保留PTN、IDS、UE显示扩展 |
| 节点字段 | 补齐独立canonical_name与interfaces；原始attributes保留；数量仍为quantity |
| 方向 | 恢复参考默认有向，不再自行将connects_to改成无向；默认箭头不是模型证据，也不表示物理网络只能单向通信 |
| 原始结果 | 返回独立extraction和raw_analysis，meta保留secondary_scenes和scene_confidence；编辑拓扑不会污染原始抽取快照 |
| 孤立节点 | 不补线；告警改成“当前抽取结果中没有关联关系，请核对原文与抽取结果”，不武断断言用户没写关系 |
| 失败 | 明确报错，不生成固定替代图；参考返回空图及错误状态，我们采用HTTP/任务失败状态 |

参考转换器另有非法ID归一化、别名端点映射、空类别回退、坐标和资源占位字段。其正常路径先要求合法唯一ID、精确端点、非空类别，这些容错分支不是合法结果必经能力。我们校验后直接保留ID和类别，不靠别名猜测端点；坐标由React布局生成，镜像和规格保持待映射，不将demo占位资源当真实资源。

## 有意保留的扩展与修正

- 跨场景实体允许主、次场景目录并集，符合secondary_scenes要求；参考只认主场景，与其自身合同不一致。
- 不按端点与显示标签二次去重，保留所有通过五字段语义校验的关系。离线重放发现参考会吞掉`CNS-TE-059`中的关系，本项目保留原关系。
- 参考转换器读取bandwidth，但Schema不允许该字段；我们补齐合同，已有值原样传递，模型漏填则留空。
- 参考示例构建器只读interface_or_link，而数据中心与城域网金标用link_or_protocol，四条示例因此丢标签。我们修正标签，将无输入依据的答案属性明确写进示例输入，实体类型与数量未变。
- 类别中文名、组合链路标签、quantity多设备卡片、避障连线、任务轮询、多模型配置、模板编辑为扩展。展开设备数量不会虚构设备接线。
